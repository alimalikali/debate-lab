# Security Policy

## Supported versions

Debate Lab is currently under active development. Security fixes are applied to
the latest version on the default branch; older commits and forks are not
supported.

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in a public issue, discussion,
or pull request.

Use GitHub's **Report a vulnerability** feature on the repository's Security
page to send a private report to the maintainers. If private vulnerability
reporting is unavailable, contact the repository owner privately and ask for a
secure reporting channel without including exploit details in the first message.

Include, where possible:

- A description of the vulnerability and its potential impact
- Affected components, versions, or commit hashes
- Reproduction steps or a minimal proof of concept
- Any known mitigations or suggested fixes
- Whether the issue has been disclosed elsewhere

You should receive an acknowledgement within seven days. The maintainers will
investigate, keep you informed of material progress, and coordinate a fix and
responsible disclosure timeline. Please allow a reasonable period for a patch
before publishing details.

## Scope

Reports about the Debate Lab source code and its maintained deployment
configuration are in scope. Vulnerabilities in third-party providers or services
should also be reported directly to the affected vendor. Never access, modify,
or retain data that does not belong to you while conducting security research.

Good-faith reports that follow this policy will not be pursued legally by the
project maintainers.
